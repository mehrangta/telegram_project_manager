## Risks

- Four simultaneous `/code` Codex phases can approximately double peak provider requests, CPU, memory, disk I/O, worktree activity, and GitHub operations compared with the current two-slot limit.
- The semaphore remains process-local, matching current architecture; running multiple main bot processes can collectively exceed four concurrent `/code` jobs.
- The queue admission limit remains 10 queued jobs, so total outstanding `/code` work can include four running jobs plus up to ten jobs in queued statuses.
- A concurrency test can become timing-sensitive unless it uses explicit synchronization primitives and bounded polling rather than fixed sleeps.
- Restarting the main bot interrupts active code phases under existing recovery semantics; rollout should use the normal controlled service restart so queued and recoverable jobs resume consistently.
