# Codex plan for mehrangta/telegram_project_manager#22

Job: `c-51ba38d3` · Revision: 1

Replace the plan-edit copy action with a native Telegram callback button that opens a reply prompt for feedback or answers. Reuse the existing code-job reply routing and `CodeJobService.edit_plan` pipeline, preserve `/code edit` as a manual fallback, keep the tracked plan notification until feedback is actually submitted, and require no database or configuration migration.

## Steps

1. **Classify plan edits as callbacks** — In the generic keyboard builder, add a narrowly scoped regex for the placeholder-stripped command `/code edit c-12345678`. When encountered, emit the existing `✏️ Edit` action label with callback data such as `edit_code_plan:c-12345678` instead of a `copy_text` button. Keep the Job ID copy button, approve/discard callbacks, pull-request URL button, issue-draft edit behavior, and copy behavior for unrelated placeholder commands unchanged. The compact payload remains safely below Telegram's 64-byte callback-data limit.
   - Likely files: `src/telegram_project_manager/platform/responses.py`, `tests/test_responses.py`
2. **Handle the edit-plan callback** — Extend callback dispatch before the generic `command:` branch. Validate the extracted job ID with the existing code-job callback pattern; acknowledge invalid data with `Button expired` and no side effects. For a valid callback, acknowledge with `Send feedback` and send a keyboard-free prompt in the callback's chat and forum topic containing `Code Job ID: <id>` plus instructions to reply with feedback or answers, with `/code edit <id> <feedback>` retained as a fallback. Do not dispatch an empty edit command and do not delete the source plan notification when the button is clicked.
   - Likely files: `src/telegram_project_manager/platform/telegram_bot.py`, `tests/test_telegram_bot.py`
3. **Reuse existing reply data flow** — Rely on the existing bot-reply parser to extract the code job ID from the prompt, `TelegramRouter` to accept an unmentioned group reply, and `CodeManager._reply_control` to classify non-control text as plan feedback. The existing control path must continue enforcing admin access, requester/admin ownership, matching chat and topic, non-empty feedback, and valid plan-edit states before calling `CodeJobService.edit_plan` with Telegram source metadata. No router, command, service, schema, or database change should be necessary unless tests expose a missing integration seam.
   - Likely files: `src/telegram_project_manager/platform/telegram_bot.py`, `src/telegram_project_manager/platform/router.py`, `src/telegram_project_manager/bots/code_manager/commands.py`, `src/telegram_project_manager/bots/code_manager/service.py`, `src/telegram_project_manager/platform/storage/db.py`
4. **Preserve notification lifecycle** — Keep `telegram_plan_message_id` intact while the edit prompt is awaiting a reply. Once feedback is accepted, the existing service flow should queue the next plan revision, dismiss the tracked plan-ready notification, refresh the main progress message, and publish the revised approval or clarification notification. This avoids stale database state and preserves approve/discard controls if the user opens the prompt but abandons it. Repeated button presses may create additional stateless prompts, but they must not mutate the job until a valid reply is submitted.
   - Likely files: `src/telegram_project_manager/bots/code_manager/progress.py`, `src/telegram_project_manager/bots/code_manager/service.py`, `src/telegram_project_manager/platform/storage/db.py`
5. **Add focused regression coverage** — Update response tests to assert that `/code edit <job> <feedback>` produces `edit_code_plan:<job>` and no longer copies the edit command. Add callback tests for valid and malformed job IDs, same-topic prompt delivery, no command dispatch, no source-message deletion, no keyboard, and prompt text containing the code job ID. Add or extend routing/manager coverage proving that a reply to this prompt reaches `edit_plan` with the expected job ID, feedback, Telegram source ID, and author. Extend plan notification assertions for both `awaiting_approval` and `awaiting_clarification` so Edit is a callback while approval remains hidden when questions are open.
   - Likely files: `tests/test_responses.py`, `tests/test_telegram_bot.py`, `tests/test_code_manager.py`
6. **Validate and roll out** — Run the focused unittest modules first, then the complete suite. Manually verify in a private chat or forum topic that tapping Edit opens the feedback prompt, replying creates the next plan revision, approve/discard still work, and the pull-request link remains available. Deploy as a normal bot code update with no migration or feature flag. Newly rendered or refreshed plan messages receive the button; previously sent Telegram messages retain their old copy action until the bot edits or replaces them.
   - Likely files: `pyproject.toml`, `uv.lock`

- Manual Telegram acceptance: create a planned code job, tap `✏️ Edit`, reply to the generated prompt, and confirm the job transitions through `queued_plan_edit`/`editing_plan` to a higher `plan_revision` with a fresh approval or clarification notification.

## Risks

- Deleting the tracked plan notification on button press would leave `telegram_plan_message_id` stale or remove approve/discard controls before feedback exists; deletion must remain tied to accepted feedback, approval, or discard.
- The callback prompt must contain the exact `Code Job ID:` field format because reply routing discovers the job through that text rather than callback state.
- A broad placeholder-command rule could convert unrelated commands from copy actions into callbacks; recognition should be limited to `/code edit` with a valid `c-` job ID.
- Old Telegram messages cannot be retroactively changed unless refreshed, so the clipboard-style Edit control may remain visible on already-sent inactive messages after deployment.
- Repeated Edit presses can create multiple prompts; they are harmless because no state changes occur until reply submission, but the tests should ensure each press does not dispatch an empty edit or delete the active controls.
