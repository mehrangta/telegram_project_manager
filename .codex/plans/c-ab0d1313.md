## Risks

- Terminal punctuation is a practical completion signal, not full natural-language semantic proof; restricting it to the three prose fields and accepting punctuation followed by closing delimiters minimizes false positives.
- A repair attempt increases model cost and latency for invalid responses. Limit the flow to two total turns and share the existing overall timeout, queue entry, semaphore slot, and Telegram status message.
- Retrying deterministic failures would waste capacity. Only local brainstorm response-validation errors should trigger repair; rendering limits, provider/authentication errors, workspace failures, cancellation, and Telegram errors should retain current immediate failure behavior.
- Resuming the same Codex thread is required so the repair request has context, but the repair prompt must request a complete replacement response to prevent partial objects or accidental reuse of a malformed field.
- The stricter validator may convert previously delivered fragments into explicit failures when both attempts remain invalid. This is preferable to silently presenting incomplete results and remains observable through existing status and error storage.
