# Codex plan for mehrangta/telegram_project_manager#74

Job: `c-71423537` · Revision: 1

The `/issues` list currently renders the latest `Codex: ready` status as plain text. Users therefore cannot jump from an issue entry back to the Telegram code-job message that contains the ready result and controls. Implement this by carrying the selected job’s Telegram identifiers through the existing repository-scoped latest-status lookup and rendering the complete `Codex: ready` label as an HTML link when the originating message is in a linkable supergroup or channel; preserve plain text as the compatibility fallback.

## Steps

1. **Extend the latest-status data contract** — In `Database.get_latest_code_job_statuses`, keep the existing repository filter, issue-number filter, and deterministic `created_at DESC, updated_at DESC, id DESC` selection semantics, but select `status`, `telegram_chat_id`, `telegram_thread_id`, and `telegram_message_id` for the chosen job. Define a `LatestCodeJobStatus` `TypedDict` with those exact fields and change the return type to `dict[int, LatestCodeJobStatus]`; construct values explicitly with integer conversion for non-null identifiers. Keep the method name to minimize churn because repository inspection found only the issue-list service and its tests as callers. No schema migration or backfill is required because all identifiers already exist on `code_jobs`.
   - Likely files: `src/telegram_project_manager/platform/storage/db.py`, `tests/test_issue_list.py`

Telegram documents both private message-link forms and the Bot API-to-channel-ID conversion. Escape the generated URL with `html.escape(..., quote=True)`, retain the GitHub issue link and copyable `/code` keyboard unchanged, and avoid Telegram API lookups during rendering.

Do not change scheduling, repository grouping, target locking, or edit-error handling. Because `render_hash` already includes the complete HTML text, a transition to ready or the later availability of a progress-message ID will change the hash and edit the newest tracked `/issues` message once; subsequent unchanged refreshes remain no-ops.

## Risks

- Telegram message URLs are documented for public or private groups and channels, with private links requiring a channel or supergroup ID; private bot chats and legacy basic groups therefore need the specified plain-text fallback. ([core.telegram.org](https://core.telegram.org/api/links))
- The latest code-job status is repository-scoped rather than chat-scoped, so a link may target a different supergroup; Telegram will deny access to users who are not members, and the implementation should not broaden or otherwise alter the current status-selection semantics.
- A user can delete the long-lived progress message after its ID is stored. The resulting link may be stale, but validating every link through Telegram during `/issues` publication or each 60-second refresh would add unnecessary network calls and failure coupling, so stale links should remain an accepted degraded case.
- Changing the status lookup from strings to structured records is an internal interface change. Updating both known callers and retaining a typed exact-key contract prevents accidental string assumptions from surviving.
- Adding HTML anchors increases message length. The 20-issue maximum-size test must use ready links to guard against exceeding Telegram’s 4096-character text limit.
